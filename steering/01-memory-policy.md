# 記憶の運用ルール

セッションをまたいで残すべき事実に出会ったら、その場で `~/.kiro/memory/` に書く。
「次から気をつける」と口で言うだけでは次のセッションに残らない。

## 記憶する条件

以下に当てはまったら記憶する。ユーザーの明示指示(「覚えて」)を待たなくてよい。

- ユーザーに訂正された / 進め方の好みを示された → type: feedback
- 環境・運用の落とし穴を踏んで解決した(接続、認証、依存、手順) → type: project
- 進行中の作業の状態・残タスク・再開手順 → type: project
- ユーザー自身のこと(役割、担当領域、使う道具) → type: user
- 外部リソースの場所(URL、ダッシュボード、課題番号、設計書のパス) → type: reference

## 記憶しないもの

- コードを読めば分かること(構造、関数名、過去の修正内容)
- git log や既存ドキュメントに書いてあること
- そのセッション限りの一時的な事情

## 書き方

```bash
cat <<'BODY' | ~/.kiro/bin/kiro-memory add <slug> <type> '<1行サマリ>'
本文。何が起きて、なぜそうなるか、次にどう使うかを書く。
feedback / project は **なぜ:** と **どう使うか:** の行を続ける。
関連する記憶は [[別のslug]] で参照する。
BODY
```

- slug は kebab-case。既存の記憶と重複しないか `kiro-memory list` で確認し、
  近いものがあれば新規作成せず**そのファイルを更新**する。
- 相対日付(「先週」「明日」)は絶対日付に直して書く。
- 間違いだと分かった記憶は `kiro-memory rm <slug>` で消す。放置しない。

索引は `kiro-memory add` / `rm` が自動で再生成する(`00-memory-index.md`)。手で編集しない。

## 思い出し方

索引は毎セッション自動で読み込まれる。本文が要るときは:

- `knowledge` ツールで「記憶」KB を検索(意味検索)
- `~/.kiro/memory/<slug>.md` を直接 read

索引に載っている記憶は「書かれた時点の事実」。ファイルパスやフラグに言及していたら、
勧める前に今も存在するか確認すること。
