# 思い出す

索引(`00-memory-index.md`)は毎セッション自動で読み込まれている。
**索引に載っていれば、そこで終わり** — slug が分かるので本文を read するだけ。

索引で見つからないときに、この順で探す。上ほど確実で速い。

## 1. 全件索引を grep する

索引は件数が多いと古いものを省略することがある（省略時は「...他 N 件」と出る）。
省略された記憶も含めた全件はここにある:

```bash
grep -i 'キーワード' ~/.kiro/memory-index-full.md
```

**言葉が分かっているならこれが一番確実。** 意味検索と違って取りこぼさない。
複数の言い方を試す（「デプロイ」「deploy」「リリース」など）。

## 2. 記憶の本文を検索する

索引はサマリしか載せていない。**記憶の中の細部**を探すならこちら:

```bash
grep -ril 'キーワード' ~/.kiro/memory/
```

## 3. KB「記憶」を意味検索する

言葉が思いつかない、言い換えが分からないときは `knowledge` ツールで意味検索する。

ただし**万能ではない**。KB が引けるのは「その記憶が何についてか」であって、
記憶の中の一節ではない。1ファイルに複数の話題が混ざった記憶は、
主題から外れた内容が引けないことがある（実測で確認済み）。
**ヒットしなかった = 存在しない、とは判断しないこと。** 1と2を先に試す。

## 4. それでも見つからないとき

- **作業ログ** — `@@WORK_LOG_DIR@@/` の直近ファイルを新しい順に読む
- **設計・仕様** — agent に登録された knowledge base を検索する（`/context` で一覧できる）
- **直近の変更** — `git log --oneline -20` と `git status`

## 注意

記憶は書かれた時点の事実。索引には更新日が併記されている。
ファイルパス・フラグ・手順に言及していたら、**今も有効か確認してから**それを前提に動く。
食い違っていたら記憶を更新する(`remember` skill)。
